# Representative Map — Design Spec

**Date:** 2026-05-10
**Project:** Lamberet Representative Map
**Goal:** Generate an accurate, exportable map of Poland showing which sales representative covers each county (powiat), driven by an Excel data file.

---

## Context

The client has an Excel file (`CRM_powiaty_FINAL.xlsx`) mapping each of Poland's ~380 powiaty to one of three sales regions and representatives. They tried ChatGPT image generation but LLMs cannot produce geographically accurate maps. This tool combines their data with real GeoJSON boundary data to generate a pixel-accurate map matching their reference image.

---

## Stack

| Tool | Purpose |
|------|---------|
| Vite + React | Dev server, component tree, state management |
| D3.js | Geo projection, SVG path rendering per county |
| SheetJS (xlsx) | Parse `.xlsx` in browser at runtime |
| GADM GeoJSON (Poland Level 2) | Accurate powiat boundary data, committed to repo |
| Node script (build-time) | Pre-process Excel → JSON |

## Data

### Excel structure (`CRM_powiaty_FINAL.xlsx`, sheet `CRM_ready`)

| Column | Values |
|--------|--------|
| Województwo | Province name (e.g. `dolnośląskie`) |
| Powiat | County name (e.g. `Wrocław`, `bolesławiecki`) |
| Region | `Północ` / `Centrum` / `Południe` |
| Handlowiec | `Handlowiec 1` / `Handlowiec 2` / `Handlowiec 3` |
| Baza | `Rumia` / `Łódź` / `Rybnik` |

380 rows total (one per powiat).

### Pre-processed JSON (`src/data/crm-data.json`)

Generated by `scripts/process-excel.js` at build time. Shape:

```json
{
  "powiaty": {
    "dolnośląskie/wrocław": { "region": "Południe", "handlowiec": "Handlowiec 3", "baza": "Rybnik" }
  }
}
```

Keys: `{województwo}/{powiat}`, both lowercased and trimmed.

### Runtime upload

SheetJS parses a user-uploaded `.xlsx` in the browser and produces the same JSON shape, replacing the bundled default in React state. No server required.

### County name matching (`src/lib/matchCounties.js`)

Matching Excel county names to GeoJSON feature names is non-trivial due to naming inconsistencies. Strategy:

1. Normalize both sides: lowercase, trim whitespace
2. Try exact match on `województwo/powiat` composite key
3. Handle city powiaty: GADM represents city counties (e.g. `Wrocław`) and rural counties (e.g. `wrocławski`) as separate features — the Excel uses plain city names for city counties, so these are matched by city name directly against the GeoJSON `NAME_2` field
4. Fall back: strip common Polish adjective suffixes (`-ski`, `-cki`, `-dzki`, `-ecki`) from rural county names and retry
5. Log unmatched counties to console so they can be fixed manually

### Color mapping

| Region | Color |
|--------|-------|
| Północ | `#4a90d9` (blue) |
| Centrum | `#6ab04c` (green) |
| Południe | `#f0a500` (orange) |

## Rendering

Both views use the same D3 pipeline: load GeoJSON → project with `d3.geoMercator` fitted to Poland's bounding box → draw `<path>` per county colored by region. They differ in what is overlaid.

### Web view (`MapView`)

- County polygons colored by region
- No county-level text labels
- Voivodeship names as larger labels
- Major city dots with labels — all 16 voivodeship capitals (Warsaw, Kraków, Gdańsk, Wrocław, Poznań, Łódź, Szczecin, Bydgoszcz, Lublin, Białystok, Katowice, Rzeszów, Olsztyn, Zielona Góra, Opole, Kielce)
- Hover tooltip: county name, region, handlowiec, baza
- No click interaction

### Export view (`ExportView`)

- All county polygons labeled with county name
- Font size small enough that all counties display a label (font auto-scales; minimum size ~6px)
- Voivodeship borders rendered with thicker stroke to distinguish from county borders
- Legend panel on the right: region colors, handlowiec name, baza city
- Title: "PODZIAŁ POLSKI NA OBSZARY DZIAŁANIA HANDLOWCÓW"
- Subtitle: "PODZIAŁ LOGISTYCZNY"
- Fixed base canvas: `1800×1200px`, scaled by user-chosen multiplier

### SVG structure (export view)

```
<svg width="{W}" height="{H}">
  <g class="counties">        ← colored polygons + county name labels
  <g class="voivodeships">    ← province border overlay (thicker stroke)
  <g class="legend">          ← right-side legend panel
  <text class="title">        ← map title
  <text class="subtitle">     ← map subtitle
</svg>
```

## Export

### SVG export
Serialize the `ExportView` SVG from the DOM. Output is fully self-contained (no external image dependencies, no tile layers).

### PNG export
1. Render `ExportView` in a hidden off-screen `div` at the chosen scale
2. Convert SVG to a Blob URL
3. Draw into an offscreen `<canvas>` via `Image` + `drawImage`
4. `canvas.toBlob('image/png')` → trigger download
5. Dispose off-screen element

No third-party screenshot library (html2canvas, puppeteer) needed — pure SVG means canvas security restrictions don't apply.

### Scale options

Base: `1800×1200px`

| Multiplier | Output size |
|------------|-------------|
| 1x | 1800×1200 |
| 2x | 3600×2400 |
| 3x | 5400×3600 |

## Out of Scope

- Click-to-highlight representative territory
- Server-side rendering or API backend
- Authentication or multi-user state
- Editing region assignments in the UI (data changes go through the Excel file)
